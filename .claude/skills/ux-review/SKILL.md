# Анализ пользовательского опыта

Методика — `method/ux-review.md`.

1. Каждый скриншот — `strat ingest <файл> --kind image`. Страница — `strat source add --kind web`.
2. Определи пользовательскую задачу и путь: какие экраны в каком порядке. Если экранов не хватает, скажи, каких именно.
3. Разбери каждый экран по чек-листу из методики. Формат наблюдения: «Экран (S#): элемент — что видно — почему может мешать — как проверить».
4. Видимое → `strat claim add "<что видно>" --type fact --sources S#`. Предполагаемое влияние на метрику → `--type hypothesis --depends C#`.
5. Не делай выводов о том, чего не видно: логики за экраном, скорости загрузки, A/B-вариантов. Если это важно, запиши как пробел.
6. Конкуренты: та же процедура и сравнительная таблица «шаг пути × продукт».
