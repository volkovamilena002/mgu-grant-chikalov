# Сопровождение решений

## После G3: зафиксировать решения
Для каждого ключевого решения из стратегии и плана проверки:
```
strat decision add --title "<что решили>" --choice "<вариант>" --owner "<роль, не ФИО>" \
  --metric "<показатель и целевое значение>" --review-on <ГГГГ-ММ-ДД> \
  --review-if "<условие пересмотра, напр. конверсия пилота < 2% через 6 недель>" --claims C3,C8,C12
```
`--claims` — утверждения, на которых держится решение. Именно по ним `update` поймёт, что решение пора пересмотреть.

## Регулярная проверка (/decisions)
1. `strat decision check`: решения с отозванными или помеченными основаниями и наступившими сроками. Те же решения видны в `strat status` и при старте сессии. Условия пересмотра (`--review-if`) автоматически не отслеживаются: сверь их с новыми данными через `strat decision check --conditions`.
2. `strat decision list`: напомни, что на ком висит.
3. Подскажи, **что решать сейчас**: сроки пересмотра на ближайшие 2 недели, решения с устаревшими основаниями, открытые вопросы (`strat q list`), которые теперь можно закрыть.
4. Основание решения заменено (`--supersedes`), а решение по сути устояло — переведи его на новые утверждения: `strat decision rebase D2 --claims C40,C41 --note "почему устояло"`. История оснований сохраняется. Делай это после согласия руководителя.
5. Решение меняется по существу: `strat decision revise D2 --note "…"` и `decision add` с новым. Выполненное или закрытое — `strat decision close D2 --note "…"`.
