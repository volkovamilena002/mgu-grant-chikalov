# Стратег Фабрики продуктов

ИИ-агент, который помогает руководителю цифрового продукта пройти путь от размытого запроса до обоснованной продуктовой и коммуникационной стратегии и не бросает его после решения.

Это папка с инструкциями, методикой, навыками, субагентами, хуками и небольшим CLI. Её открывают в Claude Code (основная среда) или в Cursor, Codex, OpenCode (через `AGENTS.md`).

## Быстрый старт (5 минут)

**Нужно:**
- [Claude Code](https://code.claude.com) (подписка Claude или `ANTHROPIC_API_KEY`) или Cursor;
- Python 3.10+;
- Git Bash на Windows (ставится вместе с Git) — нужен для хуков Claude Code.

Платные сервисы, кроме модели, не нужны.

```bash
git clone <repo> strategist && cd strategist
python tools/strat.py -h                     # проверка: CLI отвечает
python -m unittest discover -s tests         # необязательно: тесты ядра
claude                                       # открыть агента в Claude Code
```

В чате с агентом:
```
/kickoff Почему у нашего приложения X падает удержание после третьего месяца? Вот выгрузка: data/retention.csv
```

Дальше агент ведёт работу сам и останавливается на трёх воротах:
- **G1** — подтвердить бриф;
- **G2** — выбрать вариант;
- **G3** — утвердить стратегию.

**Продолжить после перерыва:** откройте новый чат. Хук `SessionStart` покажет агенту, где остановились, либо напишите `/next`.

**Необязательно:**
- `pip install -r requirements.txt` — конвертация docx/xlsx/pptx через markitdown, pandas для расчётов, расшифровка аудио;
- `cp .mcp.json.example .mcp.json` — MCP-серверы markitdown и fetch (нужен `uv`).

### В Cursor, Codex, OpenCode
Правила подхватываются из `AGENTS.md` (Cursor — ещё и `.cursor/rules/strategist.mdc`). Навыки — обычные Markdown-файлы в `.claude/skills/*/SKILL.md`: агент читает их по команде `/имя`. Хуков там нет, поэтому статус агент смотрит сам (`strat status`), расходы вносятся через `strat cost add`.

## Что агент выдаёт

В `projects/<slug>/outputs/`:

| Файл | Содержание |
|---|---|
| `01-brief.md` | вопрос, цель, получатель, ограничения, данные |
| `02-research-plan.md` | вопросы, которые могут изменить решение, методы, бюджет |
| `03-situation.md` | что известно (со ссылками), что предполагаем, чего не знаем и почему |
| `04-options.md` | ≥3 варианта, включая «оставить как есть», с возражениями red-team |
| `05-strategy-product.md` | аудитория и задача, альтернативы, направление, отказы, экономика |
| `06-strategy-comms.md` | барьер, ключевое сообщение, подтверждение, каналы, обещания ↔ продукт |
| `07-validation-plan.md` | ожидаемое изменение, сравнение, срок, нежелательные последствия |
| `00-transparency.md` | что сделано, на каких основаниях, сколько стоило и заняло времени |

Каждое существенное утверждение в документах ссылается на реестр: `[C12]` → `claims.jsonl` → источник `S4` → URL или файл.

## Ключевые решения

**1. Реестр утверждений — ядро доверия.** Каждое сведение — запись с типом `fact | hypothesis | forecast | assumption | synthetic`, источниками и зависимостями. Отсюда следует:
- факты отделены от гипотез механически, а не стилем текста;
- `strat validate` находит числа без ссылок, ссылки на отозванные утверждения и синтетику, выданную за доказательство;
- `strat impact S7` показывает, какие выводы, документы и решения затронуты новыми данными (транзитивно по графу зависимостей);
- вывод агента записывается как `hypothesis` или `forecast`, поэтому память не превращает прежний ответ в факт;
- устаревшее отзывается (`revoke`) или заменяется (`--supersedes`), история сохраняется.

**2. Процесс с воротами.** Восемь стадий, каждая оформлена навыком. CLI не пускает дальше закрытых ворот: человек принимает существенные решения, а агент сам выбирает действия внутри стадии.

**3. Раздельное хранение знаний.**
- инструкции: `AGENTS.md`, навыки, субагенты;
- методика: `method/`, только чтение;
- материалы: `inputs/`, `sources.jsonl`;
- состояние задачи: `state.json`, реестры, журнал.

Всё хранится в Markdown и JSONL, без базы данных и векторного индекса. На масштабе одного проекта (десятки источников, сотни утверждений) поиска через `grep` и графа ссылок достаточно. Такая база переносима в любую среду и читается человеком.

**4. Детерминированное ядро вместо промптов.** Всё, что можно проверить кодом, проверяет `tools/strat.py`:
- инварианты (факт без источника невозможен);
- ворота;
- идемпотентные шаги;
- журнал;
- стоимость.

Модель тратит токены на исследование и синтез, а не на бухгалтерию.

**5. Маршрутизация по стоимости.** Модели выбираются по задаче:
- синтез и общение с человеком — основная модель;
- массовое чтение источников — `researcher` (Sonnet), он заодно изолирует сырой текст от основного контекста;
- оценка и классификация — `judge` (Haiku, в 40 раз дешевле Opus);
- возражения — `red-team` (Opus, независимый взгляд).

Если `judge` оценил результат ниже порога, задачу повторяет сильная модель.

**6. Устойчивость и прозрачность.**
- `strat step start/done` не даёт незаметно повторить выполненное после сбоя;
- хуки ведут журнал обращений к сети и считают токены и деньги по стадиям;
- `strat report` собирает всё это в один отчёт.

**7. Безопасность.**
- Содержимое источников — данные, а не команды: хук ищет признаки prompt-injection и предупреждает агента.
- Домены ограничиваются на уровне проекта (`strat domain allow|block`) и проверяются хуком до запроса.
- `.env` закрыт от чтения в `settings.json` и не коммитится.
- Синтетические респонденты не могут подтвердить факт: это проверяет CLI.

## Устройство

```
AGENTS.md            постоянные инструкции (единый источник для всех сред)
CLAUDE.md            специфика Claude Code (импортирует AGENTS.md)
method/              методические знания: доказательность, JTBD, варианты, стратегии, интервью…
templates/           шаблоны итоговых документов
.claude/skills/      13 навыков: стадии процесса + interviews, data-analysis, ux-review, update, next
.claude/agents/      5 субагентов: researcher, red-team, judge, synthetic-respondent, data-analyst
.claude/hooks/       SessionStart (статус), source_guard (домены, инъекции, журнал), cost_tracker
.claude/settings.json  хуки и разрешения
config/              цены моделей, глобальные списки доменов
tools/strat.py       CLI-ядро: состояние, реестры, проверка, решения, расходы, отчёт
tools/transcribe.py  расшифровка аудио и видео (faster-whisper, необязательно)
projects/<slug>/     данные конкретной задачи
eval/                протокол сравнения с исходным способом
tests/               тесты CLI
```

## Модели, сервисы, инструменты

| Что | Зачем | Обязательно |
|---|---|---|
| Claude Opus 5.5 (основная сессия, red-team) | синтез, стратегия, критика | да (или другая сильная модель) |
| Claude Sonnet 5.5 (researcher, data-analyst, synthetic-respondent) | чтение источников, расчёты, роли | рекомендуется |
| Claude Haiku 5.5 (judge) | оценка по рубрике, классификация | рекомендуется |
| WebSearch / WebFetch (встроены в Claude Code) | открытые источники | да |
| Python 3.10+ | CLI и хуки | да |
| markitdown | docx/xlsx/pptx → Markdown | нет |
| pandas | расчёты | нет |
| faster-whisper | расшифровка аудио | нет |

Цены для подсчёта стоимости лежат в `config/pricing.json`.

## Учебный прогон

`projects/esim-travel/` — сквозной прогон на учебном брифе «туристические eSIM для оператора» (только открытые данные). Пройдены все стадии и ворота, с перерывом сессии посередине. Результаты лежат в `outputs/`, расходы и время — в `outputs/00-transparency.md`.

## Ограничения
- Агент работает только с открытыми данными и материалами пользователя. Закрытые отраслевые базы ему недоступны, и он прямо называет это пробелом.
- Аудио и видео нужно сначала расшифровать: модель их не слушает.
- Субагенты из `.claude/agents/` Claude Code подхватывает при старте сессии. Если вы создали или изменили субагента посреди сессии, откройте новый чат. Навыки подхватываются сразу.
- Автоматический подсчёт стоимости работает только в Claude Code (по транскриптам). В других средах расходы вносятся вручную.
- Модельные респонденты дают гипотезы, но не доказывают спрос.
- `strat validate` ловит формальные нарушения: нет ссылки, отозванное основание, синтетика как доказательство. Смысловую согласованность проверяет `red-team`, а окончательно — человек.
